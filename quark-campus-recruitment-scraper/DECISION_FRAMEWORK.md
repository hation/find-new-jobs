## 🎯 框架目标

### 核心目标
确保夸克校园招聘爬取器项目的所有决策都保持**清晰、一致、可追溯、可复用**。

### 具体目标
1. ✅ **决策清晰性**: 每个决策都有明确的理由和依据
2. ✅ **架构一致性**: 所有决策符合插件化架构原则
3. ✅ **文档完整性**: 每个决策都有完整记录
4. ✅ **经验传承**: 决策经验可以跨会话传承
5. ✅ **质量保证**: 决策过程有标准化质量控制

## 📋 决策框架概述

### 三层记忆系统
```
1. 📄 **项目级记忆** (永久存储)
   - DECISION_FRAMEWORK.md (本文件)
   - ARCHITECTURE.md (架构规范)
   - WORKFLOW_GUIDE.md (工作流程)
   - LESSONS_LEARNED.md (经验教训)

2. 💬 **会话级记忆** (上下文传递)
   - 会话开始时的系统提示
   - 当前项目的决策上下文
   - 必须遵守的原则列表

3. 🔧 **操作级记忆** (工具使用)
   - 工具调用前的检查逻辑
   - 决策验证机制
   - 框架符合性检查
```

### 五步决策流程
```
1. 🔍 **问题定义**: 明确要解决的核心问题
2. 📚 **信息收集**: 收集项目结构、文档、历史
3. 📊 **方案评估**: 使用决策矩阵量化评估
4. 🚀 **决策执行**: 选择最佳方案并制定计划
5. 📈 **验证调整**: 测试结果并持续优化
```

### 2. 决策矩阵 (量化评估)
| 评估维度 | 权重 | 说明 | 评分标准 (1-5) |
|----------|------|------|----------------|
| **架构一致性** | 20% | 符合插件化架构原则 | 5=完全一致, 1=冲突 |
| **维护成本** | 20% | 长期维护复杂度 | 5=成本低, 1=成本高 |
| **开发时间** | 15% | 预计实施时间 | 5=时间短, 1=时间长 |
| **测试覆盖** | 15% | 现有测试可复用性 | 5=完全覆盖, 1=无覆盖 |
| **错误风险** | 15% | 引入新问题的概率 | 5=风险低, 1=风险高 |
| **性能影响** | 10% | 对系统性能影响 | 5=提升性能, 1=降低性能 |
| **文档更新** | 5% | 文档同步工作量 | 5=无需更新, 1=完全重写 |

## 🏗️ 夸克项目专用决策原则

### 核心原则 (必须遵守)
1. **🎯 目标导向原则**: 所有决策服务于夸克项目目标
2. **🧩 架构一致原则**: 保持插件化架构的简洁性
3. **📁 文件管理原则**: 优先修改，谨慎新增
4. **🔄 迭代优化原则**: 小步快跑，持续改进
5. **📝 文档同步原则**: 决策即文档，文档即决策
6. **🛡️ 风险控制原则**: 有回退，可测试，能监控

### 文件操作原则
```
✅ **应该做的**:
1. 优先修改现有插件文件
2. 保持quark_crawler/目录结构清晰
3. 通过插件接口扩展功能
4. 更新相关文档

❌ **禁止做的**:
1. 在quark_crawler/外新增执行文件
2. 破坏插件接口兼容性
3. 跳过决策框架流程
4. 不记录决策过程
```

### 技术决策原则
1. **直接URL优先**: 优先使用direct_url方案
2. **插件化扩展**: 新功能通过插件实现
3. **记忆系统集成**: 所有操作集成记忆系统
4. **防错机制**: 基于CHECKLIST.md的防错
