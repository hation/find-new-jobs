- boss命令版本或配置问题
- API返回格式变化
- 脚本只支持JSON格式，缺乏格式适应性

#### **解决方案**
1. **创建YAML兼容脚本**: `fetch_details_yaml_fixed.py`
2. **智能解析逻辑**:
   ```python
   def parse_response(response_text):
       # 首先尝试JSON
       try:
           return json.loads(response_text)
       except json.JSONDecodeError:
           # 如果YAML模块可用，尝试YAML
           if YAML_AVAILABLE:
               try:
                   return yaml.safe_load(response_text)
               except yaml.YAMLError:
                   pass
           # 简单YAML解析（基础情况）
           if 'data:' in response_text and 'error:' in response_text:
               # 简单解析逻辑
   ```

### **问题3: token状态检测不准确**

#### **现象描述**
- 前几个security_id返回"职位不存在"错误
- 掩盖了真正的token过期问题
- 脚本无法准确判断token状态

#### **根本原因**
- 错误信息分层不清晰
- 表面错误（职位不存在）掩盖根本错误（token过期）
- 缺乏有效的token状态测试方法

#### **解决方案**
1. **错误分类与检测**:
   ```python
   # 检查特定的认证错误
   if error_code == 'not_authenticated':
       print(f"❌ Token已过期: {error_msg}")
       print(f"💡 请执行: boss logout && boss login")
       should_stop = True
   elif error_code == 200301:
       print(f"💡 职位已不存在，继续尝试下一个")
       # 不停止，继续尝试
   ```
2. **跳过测试方法**:
   - 跳过前几个可能无效的security_id
   - 从第4个未获取的security_id开始测试
3. **明确建议**:
   - 根据错误类型给出具体的下一步操作
   - 区分"需要重新登录"和"继续尝试下一个"

#### **验证结果**

## 🎯 提炼的核心原则

### **原则1: 数据格式适应性原则**
> 外部API/工具可能返回不同格式，脚本必须具备格式适应性。

**教训**: 不要假设数据格式，始终准备处理多种格式。

**实践**:
1. 实现多格式解析（JSON/YAML/XML等）
2. 保持原始数据完整性
3. 格式检测和报告

### **原则2: 数据清洗前置原则**
> 在数据处理流程的早期进行数据清洗，避免污染传播。

**教训**: 格式问题在早期解决成本最低。

**实践**:
1. 输入数据验证和标准化
2. 早期去重和清理
3. 格式一致性检查

### **原则3: 错误诊断分层原则**
> 将错误分为不同层级：表面错误和根本错误。

**教训**: 表面错误可能掩盖根本问题。

**实践**:
1. 错误分类和映射
2. 分层处理策略
3. 根本原因分析

### **原则4: 环境配置显式化原则**
> 所有环境依赖必须显式配置，避免隐式依赖。

**教训**: 隐式依赖是运行时失败的常见原因。

**实践**:
1. 显式PATH和工作目录设置
2. 依赖检查和验证
3. 明确的错误信息和修复建议

### **原则5: 字段映射验证原则**
> 数据字段映射必须基于实际数据验证，不能基于假设。

**教训**: 永远基于实际数据验证字段名。

**实践**:
1. 实际数据检查
2. 字段名映射表
3. 版本兼容性考虑

### **原则6: 保守执行策略原则**
> 在不确定的环境中，采用保守策略：失败就停止。

**教训**: 保守比激进更可靠。

**实践**:
1. 连续失败检测和停止
2. 智能跳过无效数据
3. 最大化有效资源利用率
